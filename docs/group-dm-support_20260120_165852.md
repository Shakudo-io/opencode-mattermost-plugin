# Group DM Support

**Date**: 2026-01-20
**Version**: 0.3.3
**Status**: Implementation

## Overview

Add support for group DMs (channels with type "G") in addition to 1:1 DMs (type "D"). This allows the owner to create a group DM with the bot and other users, where all participants can send prompts to OpenCode.

## Requirements

### User Access
- **All participants** in a group DM can send prompts (not just the owner)
- Bot only responds in group DMs that include the configured owner user

### Thread Scope
- Threads are **scoped per-channel**
- `!sessions` command shows only threads belonging to the current channel
- 1:1 DM threads and group DM threads are kept separate

### Session Creation Rules

| Session Origin | Thread Created In |
|----------------|-------------------|
| Prompt from 1:1 DM | 1:1 DM |
| Prompt from Group DM | That Group DM |
| OpenCode TUI / External | 1:1 DM (default) |

### Group DM Validation
- Bot responds in **any group DM** containing the owner + bot
- Owner doesn't need to be the creator of the group

## Data Model Changes

### ThreadSessionMapping

Add `channelId` field to track where the thread lives:

```typescript
interface ThreadSessionMapping {
  sessionId: string;
  threadRootPostId: string;
  shortId: string;
  mattermostUserId: string;
  dmChannelId: string;      // Owner's 1:1 DM (for notifications, fallback)
  channelId: string;        // NEW: Where thread actually lives (1:1 or group DM)
  projectName: string;
  directory: string;
  sessionTitle?: string;
  status: ThreadMappingStatus;
  createdAt: string;
  lastActivityAt: string;
  endedAt?: string;
  model?: ModelSelection;
  pendingModelSelection?: boolean;
}
```

**Key distinction**:
- `dmChannelId`: Owner's 1:1 DM channel (used for notifications, session discovery fallback)
- `channelId`: The channel where this session's thread actually exists

For TUI-originated sessions: `channelId === dmChannelId`

### Migration
Existing mappings without `channelId` default to `dmChannelId` (backward compatible).
